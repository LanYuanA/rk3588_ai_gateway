# RK3588 AI网关项目关键技术总结

## 1. 硬件加速技术

### MPP (Multi-Picture Processing)
- **功能**：Rockchip的硬件解码/编码引擎
- **优势**：大幅降低CPU负载，提高处理效率
- **应用**：视频解码（拉流）和编码（推流）

### RGA (Raster Graphic Accelerator) 
- **功能**：硬件图像处理单元
- **优势**：快速图像缩放、格式转换、合成
- **应用**：YUV到RGB转换、图像尺寸调整

### NPU (Neural Processing Unit)
- **功能**：专用AI推理处理器
- **优势**：高效的人脸检测、物体识别
- **应用**：YOLOv8模型推理

## 2. 软件架构设计

### 多线程并发模型
```cpp
// 拉流线程
puller_thread: 负责视频流拉取和解码
// 推理线程  
inference_thread: 执行AI推理任务
// 推流线程
streamer_thread: 视频拼接和推流
```

### 线程安全的数据结构
- ThreadSafeQueue：保证线程间数据安全传递
- 互斥锁：保护共享资源访问
- 条件变量：线程间同步

## 3. 性能优化策略

### 队列管理优化
- 限制队列大小防止内存溢出
- 优先处理最新帧减少延迟
- 非阻塞操作提高响应速度

### 帧率控制
- 自适应延迟机制
- 基于处理时间的动态调节
- 平衡流畅性和资源消耗

### 内存管理
- DMA32模式优化内存访问
- 预分配缓冲区减少动态分配
- 及时释放不用的资源

## 4. 视频处理流程

### 拉流阶段
1. 从不同源（设备文件、RTSP）拉取视频
2. 使用GStreamer + MPP进行硬件解码
3. YUV格式转换为RGB用于处理

### 推理阶段
1. 从队列获取待处理帧
2. 预处理图像适配模型输入
3. NPU执行AI推理
4. 保存检测结果供后续使用

### 推流阶段
1. 从各路队列获取最新帧
2. 拼接多路视频为单画面
3. 叠加检测框和标签
4. 硬件编码推送到RTSP服务器

## 5. 常见问题及解决方案

### 资源竞争问题
- **问题**：MPP同时用于解码和编码造成冲突
- **解决方案**：独立实例、时间分片、资源池管理

### 延迟问题
- **问题**：视频处理延迟过高
- **解决方案**：优先处理最新帧、减少队列积压、优化算法

### 同步问题
- **问题**：多路视频流时间不同步
- **解决方案**：统一时钟基准、缓冲区平滑、时间戳校正

## 6. 项目亮点

1. **全硬件加速**：充分利用RK3588的硬件能力

4. **稳定可靠**：完善的错误处理和资源管理
